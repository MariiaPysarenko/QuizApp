# SDD: Система онлайн-тестування (Quiz App)

## 1. Огляд і глосарій

Quiz App — вебзастосунок для тестування, автоматичного оцінювання знань і практики на основі власних помилок. Викладачі створюють квізи із запитаннями, варіантами відповідей, категорією та рівнем складності — вручну або імпортом із Google Forms. Студенти проходять опубліковані квізи, одразу отримують результат, переглядають історію спроб і повторно опрацьовують запитання, на які відповіли неправильно.

На відміну від звичайних форм для опитувань, Quiz App зберігає історію спроб кожного студента й автоматично формує практику з тих запитань, де студент помилився. Імпорт із Google Forms дає змогу не переписувати вручну тести, які викладач уже має.

**Межі першої версії (MVP):** створення та імпорт квізів, проходження з автоматичним оцінюванням, історія спроб, робота над помилками, результати для викладача, розмежування доступу за ролями.

**Поза скоупом першої версії:** гейміфікація (XP, досягнення, серії), рейтинг студентів, статистика за категоріями, імпорт через Google Forms API з OAuth, запитання з кількома правильними відповідями та відкриті запитання.

**Глосарій:**

| Термін | Значення в цьому документі |
|---|---|
| Користувач | Зареєстрована особа, яка працює із системою в ролі студента або викладача. |
| Квіз | Набір запитань зі спільною темою для перевірки знань (у коді — `Quiz`). Слово «тест» у документі вживається лише для автоматичних тестів коду. |
| Запитання | Окреме завдання квізу: текст, кількість балів і варіанти відповідей, з яких рівно один правильний. |
| Спроба | Одне проходження квізу або практики конкретним студентом із зафіксованими відповідями та результатом. |
| Категорія | Тематична група, до якої належить квіз. |
| Робота над помилками (практика) | Повторне проходження запитань, на які студент востаннє відповів неправильно. |
| Імпорт із Google Forms | Створення квізу з JSON-файлу, який експортує з Google Forms скрипт Google Apps Script. |

## 4. Архітектура

Quiz App — модульний моноліт на Java 21 без фреймворків рівня Spring. HTTP-запити приймають сервлети (Jakarta Servlet API, вбудований Apache Tomcat), бізнес-логіка живе в сервісах, доступ до даних — через інтерфейси репозиторіїв із реалізацією на чистому JDBC.

```mermaid
flowchart TD
    User["Студент / Викладач"] --> Client["Вебінтерфейс (HTML + JS)"]
    GF["Google Forms + Apps Script"] -.->|JSON-файл| Client
    Client -->|HTTP / JSON| Web["Web-шар: сервлети, фільтр автентифікації"]
    Web --> Auth["auth: реєстрація, вхід, ролі"]
    Web --> QuizM["quiz: керування квізами"]
    Web --> Import["importing: імпорт із Google Forms"]
    Web --> AttemptM["attempt: проходження та оцінювання"]
    Web --> Practice["practice: робота над помилками"]
    Import --> QuizM
    Practice --> AttemptM
    Auth --> Repo["Репозиторії (інтерфейси)"]
    QuizM --> Repo
    AttemptM --> Repo
    Practice --> Repo
    Repo --> JDBC["JDBC-реалізації"]
    JDBC --> DB[("PostgreSQL")]
```

**Шари та правило залежностей:** `web → service → domain`, `service → repository (інтерфейс)`. Доменні класи не залежать ні від сервлетів, ні від JDBC. Завдяки цьому бізнес-логіку можна тестувати за TDD з in-memory реалізаціями репозиторіїв, без бази й сервера.

**Компоненти:**

- **Вебінтерфейс** — статичні HTML-сторінки та JavaScript, що звертаються до REST API.
- **Web-шар** — сервлети приймають запити, перетворюють JSON у DTO (Jackson), викликають сервіси й повертають JSON. Фільтр автентифікації перевіряє сесію (`HttpSession`) і роль користувача.
- **auth** — реєстрація, вхід, хешування паролів, перевірка ролей.
- **quiz** — створення, редагування, публікація, архівування квізів і запитань; валідація (рівно один правильний варіант).
- **importing** — перетворення JSON-експорту Google Forms на квіз; звіт про пропущені запитання.
- **attempt** — створення спроб, перевірка відповідей, розрахунок балів, захист від повторного надсилання.
- **practice** — пошук запитань з останньою неправильною відповіддю, формування та оцінювання практики.
- **PostgreSQL** — зберігає користувачів, категорії, квізи, запитання, спроби та відповіді.
  **Технології:**

| Призначення | Технологія |
|---|---|
| Мова, збирання | Java 21, Maven |
| HTTP | Jakarta Servlet API 6, вбудований Apache Tomcat 10.1 |
| JSON | Jackson Databind |
| База даних | PostgreSQL, JDBC-драйвер `org.postgresql` |
| Хешування паролів | PBKDF2WithHmacSHA256 (стандартна бібліотека JDK) |
| Тести | JUnit 5, AssertJ, JaCoCo |

**Структура пакетів:**

```
com.quizapp
├── domain        — Quiz, Question, AnswerOption, Attempt, User, ...
├── quiz          — QuizService, QuizBuilder, QuizRepository
├── attempt       — AttemptService, AttemptRepository
│   └── scoring   — ScoringStrategy та реалізації
├── practice      — PracticeService
├── importing
│   └── googleforms — GoogleFormExport (DTO), GoogleFormsQuizAdapter
├── auth          — AuthService, PasswordHasher, UserRepository
├── persistence   — JDBC-реалізації репозиторіїв, ConnectionFactory
└── web           — сервлети, фільтр, обробка помилок, Main
```

## 5. Патерни проєктування

| Група | Патерн | Де застосовано | Навіщо |
|---|---|---|---|
| Породжувальний | **Builder** | `QuizBuilder` | Квіз складається з багатьох частин (запитання, варіанти, категорія, обмеження часу). Builder збирає його покроково і в `build()` один раз перевіряє інваріанти: є хоча б одне запитання, у кожного запитання рівно один правильний варіант. Ним користуються і ручне створення, і імпорт. |
| Структурний | **Adapter** | `GoogleFormsQuizAdapter` | Формат Google Forms (items, choices, isCorrect, points) не збігається з моделлю Quiz App. Адаптер перетворює чужий формат на `Quiz`, тож решта системи нічого не знає про Google Forms. Імпорт через Google Forms API у майбутньому — це новий адаптер, без змін у сервісах. |
| Поведінковий | **Strategy** | `ScoringStrategy`: `WeightedScoring`, `PenaltyScoring` | Правила підрахунку балів залежать від квізу: звичайне (сума балів правильних відповідей) або зі штрафом за неправильну відповідь. `AttemptService` не містить `if` за типом оцінювання, а отримує стратегію відповідно до налаштування квізу. |

Додатково використовується архітектурний патерн **Repository** (інтерфейси доступу до даних з in-memory та JDBC-реалізаціями).

```mermaid

    }
 
    QUESTION {

        string explanation "nullable"

        int position
    }
 
    ANSWER_OPTION {
        bigint id PK
        bigint question_id FK
        string text
        boolean is_correct
        int position
    }
 
    ATTEMPT {
        bigint id PK
        bigint user_id FK
        bigint quiz_id FK "nullable для практики"
        string type "QUIZ | PRACTICE"
        string status "IN_PROGRESS | COMPLETED | EXPIRED"
        datetime started_at
        datetime completed_at
        decimal score
        decimal max_score
    }
 
    SUBMITTED_ANSWER {
        bigint id PK
        bigint attempt_id FK
        bigint question_id FK
        bigint selected_option_id FK "nullable — пропущене запитання"
        boolean is_correct
    }
```

**Правила та обмеження:**

- Викладач створює багато квізів; квіз може належати одній категорії або не мати її.
- Кожне запитання має щонайменше два варіанти, з яких **рівно один** правильний. Це перевіряє `QuizBuilder` (у схемі БД таке правило не виразити простим обмеженням).
- Студенти бачать лише квізи зі статусом `PUBLISHED`. Квіз, який вже має спроби, не можна редагувати (щоб не спотворити історію), а видалення переводить його в `ARCHIVED`. Квіз без спроб видаляється повністю.
- Спроба типу `QUIZ` посилається на квіз; спроба типу `PRACTICE` має `quiz_id = NULL` і містить запитання з різних квізів.
- **Запитання вважається помилковим** для студента, якщо його **остання** завершена відповідь на це запитання неправильна. Після правильної відповіді в практиці чи повторній спробі запитання зникає з добірки.
- Обмеження часу: якщо відповіді надіслано пізніше ніж `started_at + time_limit_seconds + 30 с`, спроба отримує статус `EXPIRED`, а відповіді не зараховуються.
- `percent = score / max_score × 100` обчислюється під час читання і не зберігається.
- Аналітика й практика будуються зі збережених спроб і відповідей, тож окремо дані не дублюються.
## 7. Імпорт із Google Forms

**Як це працює:**

1. Викладач відкриває свою Google Form → «Розширення» → «Apps Script» і вставляє скрипт `tools/google-forms-export/Code.gs` з репозиторію.
2. Скрипт читає форму через `FormApp` і зберігає JSON-файл на Google Drive викладача.
3. Викладач завантажує JSON у Quiz App (`POST /api/quizzes/import/google-forms`).
4. `GoogleFormsQuizAdapter` перетворює JSON на квіз через `QuizBuilder`. Квіз створюється зі статусом `DRAFT`, щоб викладач перевірив його перед публікацією.
   **Формат експорту:**

```json
{
  "source": "google-forms",
  "formId": "1FAIpQL...",
  "title": "Основи Java",
  "description": "Контрольна з теми ООП",
  "isQuiz": true,
  "items": [
    {
      "type": "MULTIPLE_CHOICE",
      "title": "Який модифікатор робить поле видимим лише в класі?",
      "points": 2,
      "feedbackIncorrect": "Перегляньте тему інкапсуляції",
      "choices": [
        { "value": "public",  "isCorrect": false },
        { "value": "private", "isCorrect": true }
      ]
    }
  ]
}
```

**Відповідність полів:**

| Google Forms | Quiz App |
|---|---|
| `title`, `description` форми | `QUIZ.title`, `QUIZ.description` |
| `items[].title` | `QUESTION.text` |
| `items[].points` (0 або відсутнє → 1) | `QUESTION.points` |
| `items[].feedbackIncorrect` | `QUESTION.explanation` |
| `choices[].value`, `choices[].isCorrect` | `ANSWER_OPTION.text`, `ANSWER_OPTION.is_correct` |

**Що імпортується, а що пропускається:**

- `MULTIPLE_CHOICE` (радіокнопки) і `LIST` (випадний список) з рівно однією правильною відповіддю імпортуються.
- `CHECKBOX`, текстові відповіді, шкали, сітки, секції та зображення пропускаються.
- Запитання без позначеної правильної відповіді (форма не в режимі «Тест») пропускаються.
- Відповідь API містить звіт: скільки запитань імпортовано і які пропущено з причиною. Якщо не імпортовано жодного запитання, повертається 400 і квіз не створюється.
```mermaid
sequenceDiagram
    actor Teacher as Викладач
    participant API as Web-шар
    participant Import as GoogleFormsQuizAdapter
    participant Quiz as QuizService
    participant DB as PostgreSQL
 
    Teacher->>API: POST /api/quizzes/import/google-forms (JSON)
    API->>API: Перевірити роль TEACHER, розібрати JSON
    API->>Import: adapt(export)
    loop Для кожного item
        alt Підтримуваний тип і рівно одна правильна відповідь
            Import->>Import: Додати запитання в QuizBuilder
        else Інакше
            Import->>Import: Додати до списку пропущених з причиною
        end
    end
    alt Імпортовано хоча б одне запитання
        Import-->>API: Quiz (DRAFT) + звіт
        API->>Quiz: Зберегти квіз автора
        Quiz->>DB: INSERT quiz, questions, options (одна транзакція)
        API-->>Teacher: 201 Created + id квізу + звіт
    else Жодного запитання
        Import-->>API: Помилка імпорту + звіт
        API-->>Teacher: 400 Bad Request + звіт
    end
```

## 8. Ключові сценарії

### 8.1. Проходження квізу та автоматичне оцінювання

Студент починає спробу, отримує запитання без правильних відповідей, надсилає відповіді. Сервер перевіряє власника, статус і час спроби, оцінює відповіді через стратегію квізу та зберігає результат. Повторне надсилання завершеної спроби відхиляється.

```mermaid
sequenceDiagram
    actor Student as Студент
    participant API as Web-шар
    participant Attempt as AttemptService
    participant Scoring as ScoringStrategy
    participant DB as PostgreSQL
 
    Student->>API: POST /api/quizzes/{id}/attempts
    API->>Attempt: start(studentId, quizId)
    Attempt->>DB: Знайти квіз
    alt Квіз існує та опублікований
        Attempt->>DB: Зберегти спробу IN_PROGRESS
        Attempt-->>API: id спроби + запитання без правильних відповідей
        API-->>Student: 201 Created
 
        Student->>API: POST /api/attempts/{id}/submit (відповіді)
        API->>Attempt: submit(studentId, attemptId, answers)
        Attempt->>DB: Знайти спробу
        alt Спроба чужа
            Attempt-->>API: AccessDenied
            API-->>Student: 403 Forbidden
        else Спроба вже завершена
            Attempt-->>API: AlreadyCompleted
            API-->>Student: 409 Conflict
        else Час вичерпано
            Attempt->>DB: Статус EXPIRED
            API-->>Student: 409 Conflict (час вичерпано)
        else Спроба активна
            Attempt->>Scoring: score(quiz, answers)
            Scoring-->>Attempt: бали, максимум, правильність кожної відповіді
            Attempt->>DB: Зберегти відповіді, бал, COMPLETED (одна транзакція)
            Attempt-->>API: Результат
            API-->>Student: 200 OK: бал, відсоток, помилки, пояснення
        end
    else Квіз не існує або не опублікований
        Attempt-->>API: NotFound
        API-->>Student: 404 Not Found
    end
```

### 8.2. Робота над помилками

Студент отримує добірку запитань, на які востаннє відповів неправильно, відповідає на них і отримує результат. Результат зберігається як спроба типу `PRACTICE`, тому правильно розв'язані запитання зникають з наступної добірки.

```mermaid
sequenceDiagram
    actor Student as Студент
    participant API as Web-шар
    participant Practice as PracticeService
    participant Attempt as AttemptService
    participant DB as PostgreSQL
 
    Student->>API: GET /api/me/practice
    API->>Practice: buildPractice(studentId)
    Practice->>DB: Останні відповіді студента на кожне запитання
    DB-->>Practice: Відповіді
    alt Є запитання з останньою неправильною відповіддю
        Practice-->>API: Унікальні запитання без правильних відповідей
        API-->>Student: 200 OK: добірка
 
        Student->>API: POST /api/me/practice/submit (відповіді)
        API->>Practice: submit(studentId, answers)
        Practice->>Practice: Перевірити, що всі запитання є в добірці студента
        Practice->>Attempt: Оцінити та зберегти спробу PRACTICE
        Attempt->>DB: Зберегти спробу та відповіді (одна транзакція)
        Practice-->>API: Результат
        API-->>Student: 200 OK: результат і правильні відповіді
    else Помилок немає
        Practice-->>API: Порожня добірка
        API-->>Student: 200 OK: порожній список
    end
```

## 9. Ескіз API

Формат — JSON. Автентифікація — сесія (`HttpSession`, cookie `JSESSIONID`). Помилки повертаються як `{"error": "опис"}` з кодами 400 (некоректні дані), 401 (не автентифікований), 403 (немає прав), 404 (не знайдено), 409 (конфлікт стану).

**Автентифікація**

| Метод | Шлях | Призначення | Доступ |
|---|---|---|---|
| POST | `/api/auth/register` | Реєстрація. Роль `TEACHER` вимагає коду запрошення з конфігурації сервера | Гість |
| POST | `/api/auth/login` | Вхід | Гість |
| POST | `/api/auth/logout` | Вихід | Користувач |
| GET | `/api/me` | Поточний користувач | Користувач |

**Квізи та категорії**

| Метод | Шлях | Призначення | Доступ |
|---|---|---|---|
| GET | `/api/categories` | Список категорій | Користувач |
| POST | `/api/categories` | Створення категорії | Викладач |
| GET | `/api/quizzes` | Студент — опубліковані квізи; викладач — також свої чернетки | Користувач |
| GET | `/api/quizzes/{id}` | Квіз із запитаннями (правильні відповіді лише для автора) | Користувач |
| POST | `/api/quizzes` | Створення квізу | Викладач |
| PUT | `/api/quizzes/{id}` | Редагування (лише без спроб) | Автор квізу |
| POST | `/api/quizzes/{id}/publish` | Публікація | Автор квізу |
| DELETE | `/api/quizzes/{id}` | Видалення або архівування, якщо є спроби | Автор квізу |
| POST | `/api/quizzes/{id}/questions` | Додавання запитання | Автор квізу |
| PUT | `/api/questions/{id}` | Редагування запитання | Автор квізу |
| DELETE | `/api/questions/{id}` | Видалення запитання | Автор квізу |
| POST | `/api/quizzes/import/google-forms` | Імпорт із JSON-експорту Google Forms | Викладач |
| GET | `/api/quizzes/{id}/attempts` | Результати студентів за квізом | Автор квізу |

**Спроби та практика**

| Метод | Шлях | Призначення | Доступ |
|---|---|---|---|
| POST | `/api/quizzes/{id}/attempts` | Початок спроби | Студент |
| POST | `/api/attempts/{id}/submit` | Надсилання відповідей і завершення | Студент — власник спроби |
| GET | `/api/attempts/{id}/result` | Результат спроби | Власник спроби, автор квізу |
| GET | `/api/me/attempts` | Історія власних спроб | Студент |
| GET | `/api/me/practice` | Добірка для роботи над помилками | Студент |
| POST | `/api/me/practice/submit` | Надсилання відповідей практики | Студент |

## 10. Ризики та альтернативи

**Ризики:**

| Ризик | Імовірність | Вплив | Як пом'якшуємо |
|---|---|---|---|
| Несанкціонований доступ до квізів або чужих результатів | Середня | Високий: розкриття даних, зміна чужих квізів | Фільтр автентифікації; перевірка ролі та власника ресурсу в сервісах; автотести на 403 для чужих ресурсів. |
| Студент отримує правильні відповіді до завершення спроби | Середня | Високий: результати втрачають сенс | Окремі DTO для студента без `is_correct`; тест, що відповідь API їх не містить. |
| Подвійне зарахування результату через повторне надсилання | Середня | Середній: спотворена історія | Перевірка статусу спроби та оновлення в одній транзакції з умовою `status = 'IN_PROGRESS'`. |
| Формат Google Forms змінюється або містить непідтримувані типи запитань | Середня | Середній: імпорт частково не працює | Адаптер ізолює формат; непідтримувані запитання пропускаються зі звітом; тести на кожен тип item. |
| Некоректні дані квізу (немає правильної відповіді, порожні варіанти) | Середня | Середній: квіз неможливо пройти | Валідація в `QuizBuilder.build()`; квіз з імпорту створюється як чернетка. |
| Нестача часу перед контрольними точками | Висока | Високий: не всі функції готові до демонстрації | Пріоритезація MoSCoW: спершу Must-функції бекенду; вебінтерфейс — у другому спринті. |
| Сильні конкуренти (Google Forms, Moodle, Kahoot) | Висока | Низький для навчального проєкту | Фокус на відмінностях: імпорт із Google Forms і автоматична робота над помилками на основі історії. |

**Розглянуті альтернативи:**

- **Spring Boot замість сервлетів і JDBC:** відкинуто — мета проєкту полягає в тому, щоб самостійно побудувати шари та застосувати патерни, а не покладатися на фреймворк.
- **Google Forms API з OAuth замість експорту через Apps Script:** відкладено — потребує проєкту в Google Cloud і налаштування OAuth, що непропорційно складно для MVP. Завдяки Adapter його можна додати пізніше без змін у решті коду.
- **Зберігання результатів лише на клієнті:** відкинуто — історія має бути доступна після повторного входу, а результат не можна довіряти клієнту.
- **Ручна перевірка відповідей:** відкинуто — автоматичне оцінювання дає миттєвий результат і зменшує навантаження на викладача.
- **Анонімне проходження:** відкинуто — без облікового запису неможливо зберігати історію і формувати практику на помилках.
